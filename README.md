# 字幕时间轴处理

纯标准库实现的 SRT 字幕工具：时间戳解析与格式化、整体偏移、帧率换算、重叠
修正、按词断句与写回。入口在 `subtitle/core.py`，命令行为 `python -m subtitle.cli`。

## 模块说明

- `Cue(index, start_ms, end_ms, text)`：一条字幕，时间单位为毫秒。
- `parse_time(text)` / `format_time(ms)`：时间戳与毫秒互转。
- `parse_srt(path)` / `write_srt(cues, path)`：SRT 读入与写出（UTF-8、LF、
  容忍 BOM/CRLF）。
- `shift(cues, offset_ms)`：整体平移，结果钳制到非负。
- `convert_framerate(cues, src_fps, dst_fps)`：帧率换算（CLI 通过
  `--fps-from` / `--fps-to` 触发）。
- `fix_overlaps(cues, gap_ms=0, min_duration_ms=500)`：修正真正重叠，保留间隙。
- `split_long(cues, max_chars=18)`：按行宽断句，时间按文本长度比例分配。

## 时间戳规则

- 逗号与点号等价：`00:00:01,200` 与 `00:00:01.200` 都解析为 1200 毫秒，
  毫秒不会丢失；小数不足三位右侧补零（`.2` 即 200ms），超过三位截断。
- `format_time` 固定输出 SRT 标准的逗号格式，负值钳为 `00:00:00,000`。
- `shift` 负偏移后起点、终点都不小于 0，且终点不小于起点，不产生负时间。

## 帧率换算规则（23.976 ↔ 25）

23.976 fps 是有理分数 **24000/1001**（不是浮点 23.976），25 fps 就是 25。
同一批画面在不同帧率下播放，时间轴与帧率成反比：

```
新时间(ms) = 旧时间(ms) × 源帧率 / 目标帧率
```

- 23.976 → 25：乘以 (24000/1001)/25 = 960/1001 ≈ 0.95904，播放变慢方向的
  逆运算，时间戳整体缩短约 4.1%。
- 25 → 23.976：乘以 1001/960 ≈ 1.04271，时间戳整体放大约 4.27%。
- 全程用 `fractions.Fraction` 精确有理运算，只在最后一步四舍五入到整数毫秒；
  往返一次的误差不超过 2ms。

CLI 示例：

```
python -m subtitle.cli data/demo.srt --fps-from 23.976 --fps-to 25 --out out25.srt
```

## 重叠修正规则

- 只修正**真正重叠**：后一条起点早于前一条终点（或要求的 `gap_ms` 间隔）时
  才把起点后移；原本不相接的条目之间的间隙原样保留，不会被顶掉。
- 起点只会推迟、不会提前；修正后每条时长不短于 `min_duration_ms`（默认
  500ms），不足则延长终点。

## 断句规则

- 先词法化再贪心装行：英文/数字单词（含 `23.976` 这类带点号、连字符、
  撇号的形式）是不可拆分的整体；空格是软断点，换行时被消耗。
- CJK 字符之间允许断点；标点优先附在所属内容一侧，并做避头尾调整
  （行首不出现 `，。！？；：、）】」』》…` 等，行末不出现 `（【「『《“‘(` 等）。
  级联后移会把边界整体前移并向下游传递；若任何调整会使某行超过宽度上限，
  则放弃该次调整——宽度上限是硬约束（唯一例外：单个不可拆分单词本身就
  超过上限时原样保留）。
- 拆分后的各条时间连续无间隙，覆盖原条目区间，时长按各行文本长度占比
  分配，最后一条终点严格等于原终点。

## 运行

```
python -m subtitle.cli data/demo.srt --shift-ms 0 --max-chars 18 --out out.srt
python -m pytest tests -q
```
